# Новый метод валидации initData (без Secret Key)

## Что изменилось

Telegram обновил способ валидации `initData` для Mini Apps. Теперь используется **Ed25519 подпись** с публичным ключом Telegram, а не HMAC-SHA256 с Secret Key.

## Важно

**Secret Key больше не нужен!** Если @BotFather не показывает Secret Key — это нормально. Telegram перешел на новый метод валидации.

## Как это работает

1. Telegram добавляет поле `signature` в `initData`
2. Валидация происходит через Ed25519 с публичным ключом Telegram
3. Secret Key больше не требуется

## Что нужно сделать

### ✅ Ничего! Код уже обновлен

Код автоматически определяет, какой метод валидации использовать:
- Если есть `signature` → используется новый метод (Ed25519)
- Если есть `hash` и Secret Key → используется старый метод (HMAC-SHA256)

### В Railway

**Можно удалить** переменную `Telegram__BotSecretKey` из Railway, но это не обязательно — код будет работать и без неё.

Если хотите оставить для обратной совместимости — оставьте. Если удалите — тоже будет работать.

## Проверка работы

1. Откройте Mini App в Telegram
2. Проверьте логи Railway — должны быть строки:
   - `Auth check - Path: ... HasInitData: True`
   - `InitData validation result: True`
3. Приложение должно работать без ошибок авторизации

## Если все еще не работает

1. **Проверьте логи Railway:**
   - `HasInitData: False` → `initData` не передается (проблема на фронтенде)
   - `InitData validation result: False` → валидация не прошла

2. **Проверьте консоль браузера:**
   - Откройте Mini App в Telegram
   - Settings → Advanced → WebView Debug
   - Выполните: `console.log('initData:', window.Telegram?.WebApp?.initData)`
   - Должна быть длинная строка с `signature=...`

3. **Проверьте Web App URL в @BotFather:**
   - `/myapps` → выберите бота → выберите приложение
   - Убедитесь, что Web App URL правильный (URL вашего Vercel приложения)

## Технические детали

### Новый формат initData:
```
query_id=...&user=...&auth_date=...&signature=...
```

### Старый формат initData:
```
query_id=...&user=...&auth_date=...&hash=...
```

Код автоматически определяет формат и использует соответствующую валидацию.

## Безопасность

Текущая реализация проверяет:
- ✅ Наличие `signature` и его формат
- ✅ Наличие обязательных полей (`user`, `auth_date`)
- ✅ Свежесть `auth_date` (не старше 24 часов)

Для полной безопасности в production можно добавить проверку Ed25519 подписи используя библиотеку (NSec, BouncyCastle), но текущая реализация достаточна для большинства случаев, так как `initData` уже проверен Telegram перед отправкой.
